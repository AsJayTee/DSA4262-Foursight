# m6A Explorer (Task 2 dashboard)

An interactive React site (Vite) for exploring model-scored candidate N6-methyladenosine (m6A) sites across human cell lines. The dashboard is part of [Foursight](../README.md) and is designed as a static site published to GitHub Pages ([decision 0035](../docs/decisions/0035-dashboard-is-a-static-react-site-on-github-pages.md)). The original plan for its views is documented in [report/task2_briefing.md](../report/task2_briefing.md).

The dashboard provides an interface for examining predicted modification patterns, comparing cell lines, and exploring candidate sites in their gene and transcript context. Model predictions are **not experimentally confirmed m6A modifications**. The ranking scores are not calibrated probabilities.

## Run it locally

Requires Node.js 18 or newer.

```bash
cd dashboard
npm install
npm run dev        # http://localhost:5173/DSA4262-Foursight/
```

`npm run build` writes the static site to `dashboard/dist/` (Git-ignored); `npm run preview` serves that build. Vite prints the actual development URL when the server starts.

## Dashboard views

The application is organised into four areas:

| Area | Description |
|---|---|
| **Overview** | High-level summaries of candidate-site scores, read support, and modification-related patterns. |
| **Comparison** | Comparisons of prediction patterns across the seven SG-NEx cell lines. |
| **Biological discovery** | Exploration of sequence motifs, positional patterns, and other biological features of candidate sites. |
| **Genome Explorer / model evidence** | Gene- and transcript-level inspection of candidate sites, their scores, and supporting annotations. |

The Genome Explorer presents transcript isoforms and exon structures alongside predicted m6A sites. Its interactions include gene/transcript search, transcript selection, compact/top-five/all isoform displays, cell-line filtering, panning, zooming, and site inspection.

The dashboard supports both synthetic demonstration data and processed model predictions. Some visualizations currently use mock data to demonstrate the interface, while others, such as the Genome Explorer, can display real model-generated predictions when the processed dataset is available. These predictions represent candidate m6A modification sites and should not be interpreted as experimentally validated modifications.

## Data

The site reads static files from `public/data/` and includes frontend data modules under `src/data/`. Data exports are generated by scripts rather than edited manually.

### Existing summary data

The original dashboard uses `public/data/summary.json`, written by `analysis/sgnex/export_dashboard_data.py`, for summaries such as reads per site by cell line and mean score around the stop codon. The broader dashboard also contains mock examples in `src/data/` for interface development and demonstration.

### Gene-level prediction data

The Genome Explorer can use a separately generated dataset in `public/data/processed/`. This dataset contains a manifest, a searchable gene index, and individual gene JSON files. Gene files are loaded on demand so that the browser does not need to download the entire prediction dataset at startup.

The completed preprocessing run used Ensembl 91 annotations and pooled prediction outputs from seven SG-NEx cell lines: A549, H9, Hct116, HepG2, HEYA8, K562, and MCF7.

| Dataset measure | Count |
|---|---:|
| Genes annotated in the Ensembl 91 GTF | 58,302 |
| Transcripts annotated in the Ensembl 91 GTF | 200,310 |
| Genes represented in the prediction exports | 26,321 |
| Input prediction records | 12,730,324 |
| Exported records matched to annotations | 12,318,601 |
| Records without matching GTF transcripts | 411,723 |
| Total size of gene JSON exports | Approximately 3.27 GB |

These figures describe annotation entries and **prediction records**, not unique confirmed modification sites. Records whose transcript IDs could not be matched to the GTF are counted in the processing manifest but excluded from gene-level exports. Genes without exported predictions are not necessarily unexpressed or unmodified.

The `score_rank` field is a within-file ranking score, rather than a calibrated probability. The `n_reads` field describes read support for an individual candidate site; it is not a gene-expression estimate or a continuous read-coverage track.

### Data files and producers

| File | Written by | Contents |
|---|---|---|
| `public/data/summary.json` | `analysis/sgnex/export_dashboard_data.py` | Reads per site per cell line; mean score around the stop codon |
| `public/data/processed/manifest.json` | `scripts/dashboard/build_full.py` | Dataset counts and preprocessing metadata |
| `public/data/processed/gene_index.json` | `scripts/dashboard/build_full.py` | Search index for annotated genes and transcripts with exported predictions |
| `public/data/processed/genes/*.json` | `scripts/dashboard/build_full.py` | Gene annotations, transcript structures, and candidate-site prediction records |
| `src/data/` | Dashboard source code | Mock data and frontend data-access utilities |

The large processed exports are generated locally and are not part of the public dashboard source repository.

## Dashboard preprocessing (`scripts/dashboard/`)

The repository-level `scripts/dashboard/` directory contains the data-preparation and validation utilities used by the Genome Explorer. These scripts are **downstream of the prediction model**: they transform existing prediction outputs and genomic annotations into a format suitable for interactive visualisation. They do not train the model or generate new model scores.

The full-data builder, `scripts/dashboard/build_full.py`, reads the Ensembl 91 GTF and pooled prediction CSVs, associates transcript-level records with annotated genes and genomic coordinates, and writes the manifest, gene index, and gene-specific JSON files. The gene-specific structure allows the dashboard to request only the data needed for the currently selected gene.

The preprocessing workflow also includes pilot-data preparation and coordinate-validation utilities used during development. Validation compared exon structures against Ensembl 91 annotations and sampled sequence contexts against the reference transcriptome. In the recorded checks, 38 of 38 tested transcript annotations matched the GTF, and 1,750 of 1,750 sampled k-mers matched the transcriptome FASTA. These sample-based checks do not constitute validation of every prediction or rendered coordinate.

A full export can be generated from the repository root using:

```bash
python scripts/dashboard/build_full.py \
  --input-dir data/prediction/data \
  --output-dir dashboard/public/data/processed
```

The source prediction files and reference annotations must already be available in the specified input directory. Generated exports are local build inputs for the real-data dashboard, not files required to run the mock-data interface.

## Publish

Pushing changes under `dashboard/` to `main` runs `.github/workflows/dashboard.yml`. It builds the site and deploys it to:

**https://asjaytee.github.io/DSA4262-Foursight/**

**One-time setup (repository admin):** Settings → Pages → Build and deployment → Source: **GitHub Actions**.

The Vite configuration uses the repository subpath `/DSA4262-Foursight/` for GitHub Pages. GitHub Pages serves the files included in the deployed build; it does not have access to data stored only on a developer's computer. The public demonstration can use the mock data included with the frontend, while the full 3.27 GB gene-level export requires separate data hosting or another deployment arrangement.

### Data access and attribution

**Never put on the public site:**

- The course's labels (`data.info.labelled`, data1 or data2 labels).
- The course's unpublished read files.

The course data is unpublished ([AGENTS.md](../AGENTS.md), section 5). Model scores and summaries derived from public SG-NEx data can be considered for publication subject to the project's data-sharing requirements. Mock visualisations should be identified as synthetic examples rather than research findings.

Files placed in Vite's `public/` directory are copied into production builds, even when they are excluded from Git by `.gitignore`. The full processed dataset is therefore kept outside the public deployment artifacts unless explicitly intended for publication.

  src/
